## 2. GitHub での進め方（案）

### 2.1 リポジトリ

| リポジトリ | 役割 | 状態 |
|---|---|---|
| `guuu3/Codex-Project-Instructions` | 指示書・監査の報告・設計書（このリポジトリ）| 使用中 |

| `guuu3/security-company` | 別の事業（セキュリティ演習）| **yEgo とは無関係**。参照しない |

### 2.2 置く場所

```
docs/
├ audit/     Gate A の報告書・CSV（顧客の情報を含むかを確かめてから置く。J8）
├ gate-b/    Gate B の設計案と、この管理表
└ design/    承認された設計書（D1〜D9）を、Gate B の承認後にここへ移す
```

### 2.3 ルール

- 作業はブランチで行う。Gate ごとに Pull Request を1つ作り、**承認 ＝ PR のマージ**とする。
- 作業の単位は Issue にする（Gate のラベルを付ける）。案は 4章の表のとおりです。
- 顧客の PDF・画像・物件ごとの記入は、リポジトリに置かない（Gate A の検証画像と同じ扱い）。

## 5. 先に必要なこと（利用者へのお願い）

1. **yEgo 本体のリポジトリ**: GitHub にあれば名前を教えてください。無ければ作って push してください。Claude の GitHub アプリが、そのリポジトリに入れるようにしておく必要があります。
2. **Gate A の成果物**: `docs/audit/` の報告書と CSV4つ、`CLAUDE.md`、既存の設計書を push してください。
   - CSV にはファイルのパス（物件名を含む）が入っています。非公開のリポジトリでも置いてよいかを決めてください（J8）。
3. **元の PDF**: GitHub には置きません。解析は、利用者の PC で動くセッションで行う前提です。PDF を GitHub に置く運用にする場合は、別に相談させてください。
