## 3. 止まっていること（停止中）

**原本の様式第1 との一致の実測ができていない。** そのため、first-run.md の完了の定義のうち
「一致度の実測値が数値で残っている」は**未達**。様式第1 の再生成サンプルもまだ無い。

- 理由：このクラウドセッションには原本 PDF のファイルが無い。Google ドライブの接続では
  ファイルの中身が base64 で会話に流れるため、最小の報告書一式（約 290KB）でも
  現実的に取り込めない。テキストの読み取り（欄の並びの確認）だけはできた。
- 罫線と欄の座標は原本からしか取れない。推測で置くと「座標が確定しない欄は編集禁止」の原則に反するので、置いていない。

**再開の方法（どちらか）**
1. ユーザーの PC（原本があるところ）でローカルセッションを開き、§4 の手順を実行する（推奨）
2. 様式第1 のページを1枚だけ抜き出した PDF を、このセッションに直接アップロードする
   （リポジトリには入れない。作業用の一時ファイルとしてだけ使う）

## 4. 原本での実測の手順（ローカル実行用）

原本と抽出結果はリポジトリの外（例：`%USERPROFILE%\yego-work\`）に置く。

1. **罫線と文字を抽出する**：`python formkit.py extract 原本.pdf --page <様式第1のページ> -o work/raw.json`
   （記入が入っているので、リポジトリに入れない）
2. **欄の枠を決める**：raw.json の罫線から、定義 v0.1 の各欄に当たるマス目を割り当て、`rect` に入れる。
   原本と重ねて確かめたら `coord_status` を「確定」にする。1物件だけで決めない（2物件以上で同じマス目になることを確かめる）
3. **固定文字だけを定義に入れる**：`extract --fields-from <定義>` で記入を落とし、`lines` と `chars` を定義に写す。
   残った文字が `fixed_text_vocabulary` に無い場合は、記入のこぼれなので落とす
4. **再生成**：ダミーデータで `generate`
5. **実測（2種類）**：
   - (a) 定義を作った物件と比べる：抽出と再生成の道具が形を崩さないかの確認（0 に近いはず）
   - (b) **定義を作っていない別の物件**（同じ系統・版）と比べる：型としての一致の本番。
     これが議題2 Q2（合格条件）の判断材料になる（D9 の「1物件を抜いて作る試験」と同じ考え方）
6. 要約 JSON と明細 CSV を `results/yoshiki1/` に置く（記入の入らない数値だけ。CSV の `text` 列は固定文字だけになっていることを確かめる）
