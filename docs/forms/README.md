# 帳票定義と formkit（再生成・一致の実測）

最初の型の試作（`docs/first-run.md`）のために作った、帳票定義の形式と道具。
道具は `tools/formkit/`（Python。依存は `requirements.txt`）。

## 置き場所

| 場所 | 中身 | Git に入れてよいか |
|---|---|---|
| `forms/definitions/<型>/<ID>.v<版>.json` | 帳票定義（型） | はい（規定様式の構造だけ。顧客情報は持たない） |
| `forms/data/test/` | 匿名のダミーデータ | はい |
| `results/` | 実測の結果（CSV・JSON）と再生成サンプル | 匿名化したものだけ |
| 原本 PDF、抽出したままの JSON | 記入（顧客情報）を含む | **いいえ**。リポジトリの外に置く |

## 帳票定義（1ページ分）の主な項目

| キー | 意味 |
|---|---|
| `form_id` / `version` / `lineage` | 型の ID、版、生成元系統（議題2 Q3。識別値は未決） |
| `page_size` | 用紙寸法（pt）。595×842 と 595×880 は別の版として持つ |
| `lines` | 罫線 `[向き h/v, 位置, 始点, 終点, 太さ]`（pt、原点は左下） |
| `chars` | 固定文字 1字ずつ `{t, x, y(基準線), size}` |
| `fields[]` | 記入欄。`id`・`label`・`input_type`（6種）・`layer`（L2/L3）・`rect`・`coord_status`・`capacity`・`allowed` など |
| `not_fields[]` | 欄に見えるが入力欄にしないもの（例：様式第1 の ※受付欄）と理由 |
| `links[]` | PDF 内部リンク（様式第1 の設備行 → 設備様式の先頭ページ） |

入力形式 6種 → PDF の標準フォームフィールドの対応（試作で採用したもの）：

| 入力形式 | フィールド | 補足 |
|---|---|---|
| 記号 | 選択（コンボ、`/Ch`） | 選べる値は `allowed`（○×／△ など欄ごと）。空欄（未入力）と「／」は別物 |
| 選択式 | 選択（コンボ、`/Ch`） | 語彙は `allowed` |
| 数値 | テキスト（`/Tx`） | 単位は定義に持つ。数値以外（「-」など）を許すかは欄ごとに要決定 |
| 文字 | テキスト（`/Tx`） | 2行以上なら複数行フラグ。容量は `capacity`（行数・1行の文字数）と実寸の両方で確かめる |
| 日付 | テキスト（`/Tx`） | 書式は様式ごと（`format`） |
| 固定・自動 | テキスト（読み取り専用） | 台帳から写す値・自動の値 |

守っていること（計画書の原則）：
- `coord_status` が「確定」でない欄はフィールドを作らない（編集禁止）。理由は生成の記録に残る
- 入りきらない値・許容外の値は、黙って縮小せず、入れずに記録する
- 欄の外観（表示）は日本語フォントの部分埋め込みで描く。閲覧ソフトにフォントが無くても値が見える。
  後から編集するときのフォント（`/DA`）は標準の日本語 CID フォント名（非埋め込み）にしている。**最終のフォントは未決（J7）**

## 使い方

```sh
pip install -r tools/formkit/requirements.txt
cd tools/formkit
python3 formkit.py validate <定義.json>                       # 定義の形式チェック
python3 formkit.py extract <PDF> --page N [--fields-from <定義>] -o <出力.json>   # 罫線・文字の座標を取り出す
python3 formkit.py generate <定義.json> <データ.json> -o <出力.pdf>              # フォーム付き PDF を再生成
python3 formkit.py measure <原本.pdf> <再生成.pdf> --page N --definition <定義> --csv <明細.csv> -o <要約.json>
python3 formkit.py selftest --outdir ../../results/formkit-selftest              # 異常を仕込んだ試験
```

`extract --fields-from` を付けると、欄の枠の中の文字（＝記入、顧客情報）を落とし、件数だけを残す。
付けない出力には記入がそのまま入るので、リポジトリの外に置くこと。

## measure が出す数値

| 区分 | 数値 |
|---|---|
| 用紙 | 寸法の差（pt） |
| 罫線 | 原本・再生成の本数、対応した本数、片方にしか無い本数、位置の誤差（max／p95／平均、pt と mm）、端点の誤差、太さの誤差 |
| 固定文字 | 原本の固定文字数（欄の中の記入は除外し件数を記録）、対応した数、片方にしか無い数、x・y・大きさの誤差 |
| 欄 | フィールド数、罫線と重なる欄の数（**はみ出し**）、定義の枠との差 |

明細 CSV には線・文字・欄の1件ずつの対応と誤差が入る。合格の線引き（許容誤差）は**未決**
（議題2 Q2、ユーザーの決定事項）。measure は数値を出すだけで、合否は付けない。
