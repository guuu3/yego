実施：2026-11-12 ／ 実施者：もち（この VM 内に収集済みのサンプルで実施）
手順：`docs/forms/yoshiki1-first-run.md` §4（原本での実測の手順）
方針：原本 PDF と記入値はリポジトリに入れない。ここにあるのは座標・件数・誤差の数値だけ。
**合否の判定はしていない**（合格の許容誤差は議題2 Q2 でユーザー未決）。

## 対象

すべて Microsoft Print To PDF 系、用紙 595.32×841.92pt の報告書パッケージの1ページ目。

| 呼び名 | 役割 | 備考 |
|---|---|---|
| 物件A | 座標源（定義 v0.4 の罫線・固定文字・欄の矩形はここから） | 配置A |
| 物件B2 | ホールドアウト（定義作りに使っていない別物件） | 配置A。罫線が物件A と**全22本完全一致** |
| 物件B | 配置バリアントの確認用（別物件） | 配置B（後述） |

「配置」は表紙サンプル55件の枠位置の分布（下記）から付けた呼び名。
定義 v0.1 の欄の並びを作った物件（ドライブの実帳票）は座標を持たないため、
今回の座標源・ホールドアウトはどちらもその物件とは別という位置づけになる。

数値の内訳は `summary-*.json`、1件ごとの明細は `detail-*.csv`。

読み方：
- 罫線の「原本 22 本」には、ページ端にある太さ 0 の4本（不可視。元のシステムの配置枠とみられる）が
含まれる。様式の罫線ではないので定義には入れていない。どの測定でもこの4本だけが
「再生成に無い」になり、残り18本は全て対応している。
- 固定文字の「再生成にだけある 3」は日付ラベル 年・月・日。原本側では日付欄の矩形の中にあるため
measure の除外（欄の中＝記入）に引っかかるが、実際は様式の固定文字で、定義には入れてある。
- (b') で固定文字が全て未対応なのは、対応付けの探索半径（6pt）を超える 8.4pt のずれがあるため。
ずれの正体は (参考) が示すとおり**全体の平行移動**で、内部の形状は一致している。

## 画像での確認（必須項目として実施）

原本と再生成を同じ倍率で描き出し、重ね合わせ画像（一致＝黒／原本のみ＝赤／再生成のみ＝青）で確認した。

- **罫線は重ね合わせで黒一色**（ずれによる二重線なし）。枠・表・下線の位置は画像でも一致。
- 固定文字は同じ基準線・同じ位置に乗る。ただし**字形は異なる**：原本は明朝系、生成は IPA ゴシック。
文字の縁に青／赤の fringe が出るのはこの字形差で、位置の誤差ではない。フォントの最終決定は J7（ユーザー判断待ち）のまま。
- 値の表示位置：宛先・届出者・所在地／名称／用途は原本の入り方と合う。規模行の数値は右寄せで
「階」「㎡」の手前に収まる（align=right の効果）。
- 日付は1つの欄に「2026年11月12日」と入る形で、原本の「（値）年（値）月（値）日」の
間隔のある並びとは見た目が違う。欄の持ち方は系統ごとの確認事項として既存の note に残してある。
- 設備リスト（equipment_rows）：原本はリストをマス目の**縦中央に寄せたブロック**で置く
（ブロック中心の基準線 y≒341 が3物件で一致、行間 ≒11pt）。生成側の外観もブロックを
欄の縦中央に置くため置き方は一致するが、行間が 13.0pt（size×1.25）と原本より広い。

## 申し送り（Claude Code 側の課題）

1. **複数行の値が入れられない**：`check_value` が改行文字 `\n` を「フォントに無い字」と判定するため、
改行を含む値は常に落とされる。今回 equipment_rows のダミー値（2行）で再現し、
生成された欄は空になった。備考など複数行の欄全般に影響するはず。要修正。
2. 設備リストの行間：外観の行間 13.0pt に対し原本は ≒11pt。行間を定義で持てるようにするか検討。
3. 配置B への対応方針（平行移動パラメータで吸収するか、版を分けるか）は Q3 の議論材料。
実測データは本レポートと summary-b-variant*.json にある。
