## 1. 方式と材料

- 座標源と、座標決定には未使用のホールドアウト（別物件）を分けるホールドアウト方式。
  その1〜その3 は座標源1件＋ホールドアウト2件の**3物件**、別紙は多数派 geometry の2物件で照合した
- その型のサンプル全件（点検票 42パッケージ・別紙 75枚）で枠位置と系統の分布を取った（§4）
- 原本の判定「○」はベクタの円、「／」はベクタの斜線で描かれている。formkit の extract は斜線を
  水平・垂直のセグメントに分解して罫線に混ぜるため、原本側の線の集計では判定欄の中の断片を分離して
  真の罫線だけで数え直した（消火器具と同じ処理）。measure の「原本にあり再生成に無い」線と
  「罫線干渉」は、明細で断片と照合して内訳を切り分けた（§2 の各表）
- 欄内の印字ラベル（固定文字）は、「座標源・両ホールドアウトで同位置・同文字」のものだけを復元した。
  3物件で偶然一致した**記入値**（点検者名、住所の県名、電話番号の断片、内容欄の標準文言、
  その3 の測定機器の記入、別紙の区域名・個数）は復元から個別に除いた（生成スクリプトに記録）
- 再生成は定義 v0.2＋匿名ダミーデータ（`forms/data/test/*.dummy.json`）。生成できた欄は
  KOKUJI-11-1 が 123、KOKUJI-11-2 が 100、KOKUJI-11-3 が 85、JIHOKAI-BESSHI が 292（いずれも全欄）。
  値の不整合は KOKUJI-11-1 の `inspector_name` 1件のみ（仮置きの allowed にダミー名が無いため
  値が入らない。KOKUJI-01-1 と同じ既知の状態）
- 明細 CSV の同梱は §4-6（text 列が固定文字だけ）で判断した。同梱する明細は §7。
  KOKUJI-11-1 のホールドアウト明細は、製造者名の記入値の先頭字1字が text 列に入るため同梱せず要約のみとする。
  別紙バリアントの明細は対象系統ではない参考測定のため同梱しない

## 3. 様式固有の確認事項

1. **集計表の有無**：その1〜その3 に集計表は無い。別紙には**合計行**がある（感知器16列＋地区音響装置・
   発信機の列合計が最終行に入る）。合計の欄は `固定・自動` として定義したが、formkit のルール種別に
   集計が無いため計算式は定義に持たない（§6 の申し送り4）。消火器具その2 の器種別集計表のような
   「表があるのに欄が無い」不足はこの型には無い
2. **枚数欄の有無**：4型すべてに**無い**。別紙は台帳系で1〜17シート/物件に増えるが、
   （i/n）形式の枚数表示は全75枚のどこにも無い（消火器管理票と同じ）。付けるかは package 生成側の決定事項
3. **判定記号の運用**：その1〜その3 は様式の備考3 で ○＝正常、×＝不良（不良内容欄に記入）、
   備考6 で ※印の欄は自動試験機能を有するものは記入不要とされ、実帳票では該当なしに**／**が入る。
   **△ は42パッケージのどこにも観測されなかった**。選択肢のある欄は該当事項に○を付す（備考4、原本ではベクタの円）。
   別紙の点検結果も ○＝正常・×＝不良（その備考4）。定義の判定欄は allowed を ○・×・／ とし、
   × のとき不良内容を必須にするルール（required_if）を付けた
4. **頭の部分**：名称・点検年月日・点検者などの頭部は**その1 のみ**。その2・その3・別紙には無い
5. **点検種別**：全42件が「機器・総合」で、位置も含めて印字固定だったため欄にしない（not_fields に記録。
   機器のみ・総合のみの帳票が現れたら欄化が要る）
6. **日付の書式**：固定スロット（§2.1）。和暦・西暦の両用があるため、定義の値はどちらの表記も受けられる前提で
   format に記録した

## 6. 申し送り・残課題

1. **formkit の集計の会計（Claude Code 側）**：判定印（○・／）がベクタ描画のため、measure の線の集計に
   断片として混ざり、「罫線干渉」にも数えられる。今回は明細 CSV と断片リストの照合で切り分けたが、
   欄内のセグメントを文字と同様に比較から外す仕組みがあると、要約だけで内訳が読める
2. **formkit の既知の不具合2件は未対応のまま**（Claude Code 側の単位）：①複数行の値が改行の判定で落ちる、
   ②定義の `capacity` が null だと generate が TypeError。今回の定義は全欄に容量の実測・設定値を入れて
   回避し、ダミーも1行の値で検証したため、どちらも踏まなかった
3. **別紙の備考高さバリアント（14/75枚）**：多数派より備考域が 19.44pt 短い系統がある。
   平行移動（配置B の原点ずらし）では吸収できない差で、系統ごとの扱い（議題2 Q3）の判断が要る。
   あわせて PDFlib 系（別紙2枚・点検票2件）と別紙の行位置の異なる系統（4枚）も未確定
4. **別紙の合計行の自動集計**（機能設計側）：合計欄は定義したが、formkit のルール種別に集計が無い。
   13行を超えてシートが増える場合の合計行の置き方（各シートか最終シートか。原本では各シートの
   最終行に合計がある）も package 生成側の設計が要る
5. **その2 の選択肢の値の持ち方**（機能設計側）：選択肢は印字＋○付けが原本の方式。選ばれた選択肢を
   データとしてどう持つか（選択式の別欄にするか、内容欄のテキストに含めるか）の判断が要る
6. **点検者名の語彙**：KOKUJI-11-1 の `inspector_name` の `allowed` は仮置き
   （「（点検者台帳から。台帳は未作成）」）のまま。別記様式第3（点検者一覧表）の定義と台帳の形が決まれば差し替える
7. **配置B の直接の取り直し**：その1〜その3 の配置B（4件）は様式第1 の (b) と同じ残件
8. **原本の「縮小して入れる」記入と formkit 方針の差**：その3 の測定機器表では、長い型式等が
   9.72〜6.12pt に縮小して記入されている。formkit は縮小せず「入りきらない値は入れない」方針のため、
   実データ投入時に長い値の運用が異なる（消火器具と同じ論点）
